Operating System

1. What is an Operating System?

An Operating System (OS) is software that sits between you (apps) and the hardware. Think of it as a manager of a restaurant: customers (programs) place orders, and the manager decides who gets the kitchen (CPU), tables (memory) and storage (disk).

👤User
📱Apps
⚙️OS
🧠Hardware

Two roles of an OS

  • Resource manager: shares CPU, RAM, disk and devices fairly and safely among programs.
  • Extended machine (abstraction): hides ugly hardware details. You say "save file", not "move disk head to sector 4821".

Main functions

  • Process management: create, schedule, end programs.
  • Memory management: give RAM to programs and protect it.
  • File management: store and organise data.
  • Device (I/O) management: control keyboard, disk, printer using drivers.
  • Security and protection: users, permissions, isolation.
  • Networking and user interface: sockets, GUI/CLI shell.

Kernel, System Calls, User vs Kernel mode

The kernel is the core of the OS. Normal programs run in user mode (limited power). When they need something special (read a file), they make a system call, and the CPU switches to kernel mode (a hardware mode bit changes from 1 to 0) to do it safely, then switches back. This is called dual-mode operation and it stops a buggy program from damaging the system.

Programmers usually call a library function (like printf), which internally makes the real system call (write). The set of such functions is the API.

Interrupts and traps

  • Interrupt: a signal from hardware (keyboard press, disk finished, timer). The CPU stops, runs an interrupt handler, then resumes.
  • Trap / exception: raised by software: a system call, divide by zero, page fault.
  • Timer interrupt: fires regularly so the OS can take the CPU back from a running program. This is how preemptive scheduling works.

OS structures

💡 Monolithic kernel: everything inside the kernel (Linux). Fast, but one bug can crash all. Microkernel: only the minimum inside (scheduling, IPC, memory), rest in user space (more secure, slightly slower). Hybrid: mix of both (Windows, macOS). Layered: OS built in layers, each uses only the layer below.

What happens when you press the power button? (Boot process)

  1. Firmware (BIOS/UEFI) runs POST (Power-On Self Test) to check hardware.
  2. Firmware finds the boot device and loads the bootloader (GRUB, Windows Boot Manager).
  3. Bootloader loads the kernel into RAM.
  4. Kernel starts drivers and the first process (init / systemd, PID 1).
  5. Login screen / shell appears.

Virtual machines and containers

  • Virtual Machine (VM): a hypervisor (VMware, VirtualBox, KVM) fakes a complete computer, so many full OSes run on one machine. Heavy but strongly isolated.
  • Container (Docker): shares the host kernel, but isolates processes using Linux namespaces and cgroups. Lightweight and starts in seconds.

2. Process, Threads & IPC

A program is a file on disk (passive). A process is a program in execution (active). Each process has its own memory:

High address
+------------------+
|      Stack       |  function calls, local variables (grows down)
|        |         |
|        v         |
|   (free space)   |
|        ^         |
|        |         |
|      Heap        |  malloc/new, dynamic memory (grows up)
+------------------+
|   Data section   |  global and static variables
+------------------+
|   Code (text)    |  the instructions
+------------------+
Low address

Every process has a PCB (Process Control Block) which stores its ID (PID), state, program counter, CPU registers, scheduling info, memory info and open files.

📌 Two schedulers move processes: the long-term scheduler (job: New → Ready, controls how many programs are in memory), the short-term scheduler (CPU scheduler: Ready → Running, runs very often) and the medium-term scheduler (swaps processes out of and into RAM).

Context Switch

When the CPU changes from one process to another, the OS saves the old PCB and loads the new one. This is a context switch. It is pure overhead, because no useful work happens during it.

Creating processes: fork, exec, wait

  • fork() creates a child that is a copy of the parent. It returns 0 to the child and the child's PID to the parent.
  • exec() replaces the current program in the process with a new program.
  • wait() makes the parent wait until the child ends.
pid = fork();
if (pid == 0) {
    execl("/bin/ls", "ls", NULL);   // child runs ls
} else {
    wait(NULL);                      // parent waits
    printf("Child finished\n");
}
💡 Counting trick: if a program calls fork() n times in a row (no conditions), the total number of processes is 2n (including the original), so 2n − 1 new children. 3 forks → 8 processes.
  • Zombie: child has finished, but the parent has not called wait(), so its entry stays in the process table.
  • Orphan: parent ended before the child. The child is adopted by init/systemd.

Why use threads?

  • Responsiveness: UI stays alive while another thread downloads.
  • Resource sharing: no copying of memory.
  • Economy: cheaper to create and switch.
  • Scalability: use many CPU cores in parallel.

Multithreading models: Many-to-One, One-to-One (Linux, Windows) and Many-to-Many.

Concurrency vs Parallelism: concurrency = many tasks in progress by taking turns (one chef, many dishes). Parallelism = tasks really running at the same instant (many chefs).

3. CPU Scheduling

Many processes are ready but there is only one CPU. The scheduler decides who runs next. Goals: high CPU use, high throughput, low waiting time, fast response, fairness.

Important terms

  • Arrival Time (AT): when the process enters the ready queue.
  • Burst Time (BT): CPU time needed.
  • Completion Time (CT): when it finishes.
  • Turnaround Time (TAT) = CT − AT
  • Waiting Time (WT) = TAT − BT
  • Response Time (RT) = time of first CPU − AT
  • Throughput = processes finished per unit time. CPU utilisation = % time CPU is busy.
  • Dispatcher: the module that actually gives the CPU to the chosen process (its delay is dispatch latency).

Preemptive = OS can take the CPU away. Non-preemptive = process keeps the CPU until it finishes or waits.

Multilevel QueueSeparate queues (system, interactive, batch), each with its own algorithmYesFixed queues can starve lower ones
Multilevel Feedback QueueProcesses move between queues based on behaviour (CPU hogs go down, I/O-bound stay up)YesComplex to tune
💡 SJF/SRTF gives the minimum average waiting time (provably optimal), but burst time is not known in real life, so it is predicted from past bursts (exponential averaging).

Multilevel Feedback Queue (MLFQ) in simple words

  1. New process enters the top queue (small quantum, highest priority).
  2. If it uses its full quantum, it is moved down (it looks like a CPU hog).
  3. If it gives up the CPU early (waits for I/O), it stays up (it looks interactive).
  4. Processes waiting too long in a low queue are moved up (aging).

Other scheduling topics

  • Multiprocessor scheduling: one common queue vs one queue per core. Processor affinity tries to keep a process on the same core to reuse its cache. Load balancing spreads work evenly.
  • Real-time scheduling: Rate Monotonic (shorter period = higher fixed priority) and EDF (Earliest Deadline First, dynamic priority).
  • Linux CFS: the "Completely Fair Scheduler" gives each process a fair share of CPU using a virtual runtime kept in a red-black tree.
  • Priority inversion: a high-priority task waits for a lock held by a low-priority task, while a medium-priority task keeps running. Fix: priority inheritance (the low task temporarily gets the high priority). It famously caused resets on the Mars Pathfinder.

4. Synchronization

When many processes or threads use the same shared data, results can go wrong. Example: two people withdraw money from the same account at the same moment. This is a race condition: the result depends on who runs first.

✍️ Why counter++ is not safe

counter++ is really 3 steps: (1) load counter into a register, (2) add 1, (3) store back.
Counter = 5. Thread A loads 5. Thread B loads 5. A stores 6. B stores 6.
Two increments happened, but counter is 6, not 7. An update was lost.

Critical Section Problem

The critical section is the code that touches shared data. Every process has this shape: entry section → critical section → exit section → remainder section. A correct solution needs:

  1. Mutual Exclusion: only one process inside at a time.
  2. Progress: if nobody is inside, someone who wants to enter must be allowed (decision cannot be postponed forever).
  3. Bounded Waiting: no process waits forever.

Software solution: Peterson's algorithm (2 processes)

// shared: boolean flag[2] = {false, false}; int turn;
// Process i (j is the other one)
flag[i] = true;          // I want to enter
turn = j;                // but you go first if you also want
while (flag[j] && turn == j) ;   // busy wait
    /* CRITICAL SECTION */
flag[i] = false;         // I'm done

It satisfies all 3 conditions, but on modern CPUs (instruction reordering) it needs special hardware support to be reliable.

Hardware support

  • Test-and-Set / Compare-and-Swap: atomic instructions (cannot be interrupted halfway) that read and change a lock variable in one step.
  • Spinlock: a lock built on those; the waiting thread loops (busy waiting). Good only if the wait is very short, or on multi-core.
  • Disabling interrupts works only inside the kernel on a single CPU.

Tools

  • Mutex: a lock with an owner. Only the one who locked it can unlock it.
  • Semaphore: an integer counter. wait(S) (also P) decrements (blocks if 0), signal(S) (also V) increments. Binary (0/1) acts like a lock. Counting manages N identical resources.
  • Monitor: a high-level construct where only one thread can be inside at a time, with condition variables (wait/signal). Example: Java synchronized.
💡 Semaphore value meaning: positive = how many resources are free. Zero = none free. Negative (in the textbook definition) = how many processes are waiting.

Classic 1: Producer–Consumer (bounded buffer)

semaphore mutex = 1, empty = N, full = 0;

Producer:                 Consumer:
  wait(empty);              wait(full);
  wait(mutex);              wait(mutex);
  add item to buffer;       remove item from buffer;
  signal(mutex);            signal(mutex);
  signal(full);             signal(empty);

empty counts free slots, full counts filled slots, mutex protects the buffer itself. Warning: swapping the order of wait(empty) and wait(mutex) can cause a deadlock.

Classic 2: Readers–Writers

Many readers may read together, but a writer needs exclusive access. In the "first readers–writers" solution the first reader locks out writers and the last reader lets them in again, using a read_count protected by a mutex and a wrt semaphore. Problem: writers may starve.

Classic 3: Dining Philosophers

5 philosophers sit around a table with 5 chopsticks (one between each pair). To eat, a philosopher needs both neighbours' chopsticks. If everyone picks up the left one at the same time, all wait forever (deadlock).

  • Allow at most 4 philosophers to sit at once.
  • Pick up both chopsticks only if both are free (inside a critical section).
  • Asymmetric rule: odd philosophers pick left first, even pick right first.
📌 Mutex vs Semaphore: mutex = locking (ownership), semaphore = signalling (counter, no owner).

5. Deadlock

A deadlock is when a group of processes are all waiting for resources held by each other, so none can ever proceed. Like two cars on a one-lane bridge, each refusing to reverse.

Resource use order: request → use → release.

🎬 Watch a deadlock happen

4 Necessary Conditions (all must hold)

  1. Mutual Exclusion: resource can be used by only one process.
  2. Hold and Wait: process holds one resource and waits for another.
  3. No Preemption: resource cannot be forcibly taken away.
  4. Circular Wait: P1 → P2 → ... → Pn → P1 chain of waiting.

Resource Allocation Graph (RAG)

  • Circles = processes, squares = resources (dots inside = instances).
  • Request edge: P → R. Assignment edge: R → P.
  • No cycle → no deadlock. Cycle with single-instance resources → deadlock. Cycle with multi-instance resources → possible deadlock.
P1 --requests--> R2        R1 --held by--> P1
P2 --requests--> R1        R2 --held by--> P2
Cycle: P1 -> R2 -> P2 -> R1 -> P1   => DEADLOCK

How to handle it

MethodIdea
PreventionBreak at least one of the 4 conditions (e.g. number resources and always request in order → no circular wait; request everything at once → no hold and wait)
AvoidanceGrant a request only if the system stays in a safe state (Banker's Algorithm)
Detection & RecoveryAllow deadlock, detect using a graph or algorithm, then kill a process or take resources back
Ignore (Ostrich)Pretend it never happens. Used by Windows and Linux
📌 Safe state = there exists an order (safe sequence) in which every process can finish. Safe → no deadlock. Unsafe → deadlock may happen (not always).

Banker's Algorithm in short

It keeps tables: Allocation, Max, Need = Max − Allocation, Available. It looks for an order where every process can finish with the available resources (a safe sequence). If one exists, the state is safe.

✍️ Worked example: 5 processes, resources A, B, C (total 10, 5, 7)

Allocation: P0 (0,1,0) · P1 (2,0,0) · P2 (3,0,2) · P3 (2,1,1) · P4 (0,0,2)
Max: P0 (7,5,3) · P1 (3,2,2) · P2 (9,0,2) · P3 (2,2,2) · P4 (4,3,3)
Available = total − allocated = (3,3,2)

Need = Max − Allocation: P0 (7,4,3) · P1 (1,2,2) · P2 (6,0,0) · P3 (0,1,1) · P4 (4,3,1)

Find a safe sequence (Work starts at (3,3,2)):
1. P1 need (1,2,2) ≤ (3,3,2) ✔ → after P1 finishes, Work = (3,3,2)+(2,0,0) = (5,3,2)
2. P3 need (0,1,1) ≤ (5,3,2) ✔ → Work = (5,3,2)+(2,1,1) = (7,4,3)
3. P4 need (4,3,1) ≤ (7,4,3) ✔ → Work = (7,4,3)+(0,0,2) = (7,4,5)
4. P0 need (7,4,3) ≤ (7,4,5) ✔ → Work = (7,4,5)+(0,1,0) = (7,5,5)
5. P2 need (6,0,0) ≤ (7,5,5) ✔ → Work = (10,5,7)
Safe sequence: <P1, P3, P4, P0, P2>. The state is safe.

Detection and recovery

  • Detection: run a Banker-like algorithm (or look for a cycle in the wait-for graph) periodically.
  • Recovery by terminating: kill all deadlocked processes, or one at a time until the cycle breaks.
  • Recovery by preemption: take a resource from a victim, roll back that process, and avoid always choosing the same victim (starvation).
💡 Deadlock vs Starvation: in deadlock, nobody in the group can ever move. In starvation, the system moves on but one process is never chosen.
INTERMEDIATE

6. Memory Management

The OS must give each process memory and protect it from others. Programs must be in RAM to run. Disks are too slow, and registers and cache are too small.

Speed:  Registers > Cache > RAM > SSD/Disk
Size:   Registers < Cache < RAM < SSD/Disk

Logical vs Physical address

A program uses logical (virtual) addresses. The hardware MMU converts them to physical addresses in RAM. With simple contiguous allocation the MMU uses a base (relocation) register and a limit register: physical = base + logical, and if logical ≥ limit the hardware raises a trap (protection).

Swapping

A process can be moved out of RAM to disk (swap out) and brought back later (swap in), so more processes can exist than RAM can hold.

Contiguous allocation: where to put a process in free holes?

StrategyIdea
First FitFirst hole big enough. Fast.
Best FitSmallest hole that fits. Leaves tiny useless holes.
Worst FitLargest hole. Leaves big leftover, usually worst in practice.
Next FitLike first fit, but continue from the last allocation.
✍️ Example: holes 100K, 500K, 200K, 300K, 600K. Place 212K, 417K, 112K, 426K

First fit: 212→500K (leaves 288K), 417→600K (leaves 183K), 112→288K hole, 426→cannot fit (no hole ≥ 426K left).
Best fit: 212→300K, 417→500K, 112→200K, 426→600K (all four placed).
Worst fit: 212→600K (leaves 388K), 417→500K, 112→388K hole, 426→cannot fit.
Best fit wins here, but results change with the data.

Fragmentation

  • Internal: wasted space inside an allocated block (fixed partitions, last page of a process).
  • External: free memory exists but is scattered in small holes. Fix: compaction (slide everything together) or paging.

Paging

Memory is cut into equal blocks: pages (logical) and frames (physical), same size. A page table maps page number → frame number. There is no external fragmentation, only a little internal fragmentation in the last page.

Logical address = [ Page number | Offset ]
Physical address = [ Frame number | Offset ]

Example: page size 1 KB, page 2 → frame 5, offset 100
Physical address = 5 × 1024 + 100 = 5220
✍️ Example: address bits

Logical address = 16 bits, page size = 1 KB (210).
Offset bits = 10. Page number bits = 16 − 10 = 6. So there are 26 = 64 pages.
If physical memory is 64 KB (216), there are 216/210 = 64 frames.

TLB (Translation Lookaside Buffer) is a small, very fast cache of recent page-table entries. A TLB hit avoids an extra memory access to the page table in RAM.

Effective Access Time = hit% × (TLB + mem) + miss% × (TLB + 2 × mem)

✍️ Example: TLB 20 ns, memory 100 ns, hit ratio 80%

EAT = 0.8 × (20 + 100) + 0.2 × (20 + 200) = 96 + 44 = 140 ns.
Without a TLB every access costs 200 ns (page table + data), so the TLB saves 30%.

Page table tricks for big address spaces

  • Multilevel (hierarchical) page table: page table itself is paged; only needed parts exist in RAM.
  • Hashed page table: hash the page number to find the entry.
  • Inverted page table: one entry per frame (not per page), saves memory but search is slower.
  • Extra bits in each entry: valid/invalid, read/write/execute protection, dirty, reference.
  • Shared pages: read-only code (like a library) can be mapped by many processes.

Segmentation

Memory is split by logical parts (code, stack, heap) of different sizes. A logical address is (segment number, offset). The segment table stores base and limit of each segment. It matches how programmers think, but suffers external fragmentation.

PagingSegmentation
Fixed-size blocksVariable-size blocks
Invisible to programmerVisible to programmer
Internal fragmentationExternal fragmentation
Page table (page → frame)Segment table (base + limit)

Segmented paging (used in x86 history) cuts each segment into pages to get the benefits of both.

7. Virtual Memory & Page Replacement

Virtual memory lets a program run even if it is bigger than RAM. Only needed pages stay in RAM, the rest stay on disk (in the swap space). This is demand paging: load a page only when it is first used ("lazy loading").

Benefits: programs larger than RAM, more processes in memory at once, simpler programming, easy sharing and protection.

Page Fault

  1. CPU asks for a page that is not in RAM (valid bit = invalid) → page fault (trap to OS).
  2. OS checks the address is legal. If illegal → terminate process (segmentation fault).
  3. OS finds the page on disk.
  4. OS finds a free frame (or replaces one; if the victim is dirty, it is written back first).
  5. Page is read from disk into the frame (the process waits; CPU runs another process).
  6. Page table updated (valid bit = 1), instruction restarts.
✍️ Effective access time with page faults

Memory access = 200 ns, page-fault service time = 8 ms = 8,000,000 ns, page fault rate p = 1/1000.
EAT = (1 − p) × 200 + p × 8,000,000 = 199.8 + 8000 = ≈ 8200 ns.
One fault in 1000 accesses slows the machine 40 times. That is why the fault rate must be tiny.

Page Replacement Algorithms

  • FIFO: remove the oldest page. Simple, but can suffer Belady's Anomaly (more frames → more faults!).
  • LRU: remove the page not used for the longest time. Good, no anomaly (a "stack algorithm"). Needs hardware help (counters or a stack).
  • Optimal: remove the page that will not be used for the longest time in the future. Best possible, but impossible to implement in real life (used as a benchmark).
  • Clock (Second chance): a cheap approximation of LRU using a reference bit; a page with bit 1 gets a second chance (bit cleared, skip it).
  • LFU / MFU: based on usage counts.
📌 For the standard string 7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1 with 3 frames: FIFO = 15 faults, LRU = 12 faults, Optimal = 9 faults. Run it below to check.

Frame allocation

  • Equal: same frames to each process. Proportional: bigger process gets more.
  • Global replacement: a process may take frames from any process. Local replacement: only from its own frames.

Thrashing

When the system spends more time swapping pages than executing, performance collapses. It happens when too many processes compete for too few frames: CPU use drops, so the OS adds more processes, which makes it even worse. Fixes: reduce multiprogramming, use the working set model (give each process the pages it used in the last Δ references) or the page-fault frequency method, or add RAM.

Copy-on-Write (COW)

After fork(), parent and child share the same pages (marked read-only). Only when one of them writes, that single page is copied. This makes fork() very fast and saves memory, especially when the child calls exec() right away.

Memory-mapped files

A file is mapped into the address space, so reading and writing memory reads and writes the file (mmap()). It is also how shared libraries and shared memory work.

8. File System, I/O & Disk Scheduling

What is a file?

A file is a named collection of related data on storage. Its attributes: name, type, location, size, protection, timestamps. Operations: create, open, read, write, seek, delete, truncate, close.

  • Access methods: sequential (one byte after another), direct/random (jump to any block), indexed.
  • Open-file tables: a system-wide table plus a per-process table keep track of open files; the file descriptor (a small number such as 0, 1, 2 = stdin, stdout, stderr) is an index into it.

  • Soft (symbolic) link: a small file containing a path. Breaks if the target is deleted. Can cross file systems.

Free-space management

  • Bitmap: 1 bit per block (0 = free, 1 = used). Easy to find contiguous space.
  • Linked list of free blocks, grouping, counting (start + number of blocks).

File system safety

  • Journaling (ext4, NTFS): write the planned change to a log first, so after a crash the system can finish or undo it quickly.
  • Buffer cache / page cache: recently used disk blocks stay in RAM.
  • Common file systems: FAT32, NTFS (Windows), ext4 (Linux), APFS (macOS).

Linux file permissions

-rwxr-xr-- means: file type (- file, d directory), then owner = rwx, group = r-x, others = r--. Each r = 4, w = 2, x = 1, so chmod 754 file gives owner 7 (rwx), group 5 (r-x), others 4 (r--).

How I/O works

  • Device driver: software that knows how to talk to one specific device.
  • Polling: CPU keeps asking "are you done?" (wastes CPU).
  • Interrupt-driven I/O: device interrupts the CPU when done.
  • DMA (Direct Memory Access): a DMA controller moves a whole block between device and RAM without the CPU, and interrupts only once at the end. Best for big transfers.
  • Buffering smooths speed differences, caching keeps copies, spooling queues output (print queue).

Disk basics

A hard disk has platters → tracks → sectors. Access time = seek time (move head to the track) + rotational latency (wait for the sector to spin under the head) + transfer time. Seek time is the slowest part, so we reorder requests. (SSDs have no moving parts, so disk scheduling matters little for them.)

Disk scheduling

  • FCFS: serve in arrival order.
  • SSTF: nearest track first (can starve far requests).
  • SCAN (Elevator): move one direction to the end, then reverse.
  • C-SCAN: go one way, jump back to start, no service on return (more uniform waiting).
  • LOOK / C-LOOK: like SCAN but turn at the last request, not the disk end.
✍️ Worked example: requests 98, 183, 37, 122, 14, 124, 65, 67. Head at 53. Disk tracks 0–199

FCFS: 53→98→183→37→122→14→124→65→67 = 45+85+146+85+108+110+59+2 = 640 tracks.
SSTF: 53→65→67→37→14→98→122→124→183 = 12+2+30+23+84+24+2+59 = 236.
SCAN (moving towards 0 first): 53→37→14→0 then up to 183 = 53 + 183 = 236.
LOOK (towards 0 first): 53→37→14 then up to 183 = 39 + 169 = 208 (it does not go to 0).

9. Protection & Security

Protection controls which process or user may use which resource inside the system. Security defends against threats from outside and inside (attackers, malware).

Protection mechanisms

  • Dual mode and memory protection (base/limit, page permissions) stop programs from touching the kernel or each other.
  • Access Control Matrix: rows = users/domains, columns = objects, cells = rights. Stored as ACL (per object: who can do what) or capability list (per user: what they hold).
  • Principle of least privilege: give only the rights needed.
  • Rings: CPU privilege levels (ring 0 = kernel, ring 3 = user).

Authentication (who are you?)

  • Something you know (password), have (phone, key), are (fingerprint). Multi-factor combines two or more.
  • Passwords must be stored as salted hashes, never as plain text.

Common threats

Defences

  • ASLR (random memory layout), DEP/NX (data pages not executable), stack canaries against buffer overflows.
  • Regular updates, antivirus, firewall, backups, sandboxing and encryption (BitLocker, LUKS).

Daemons and services

A daemon is a background process with no terminal (web server, scheduler). systemd starts and manages them (systemctl start/stop/status).

Real-time OS (RTOS)

Predictability beats raw speed. Features: priority-based preemptive scheduling, tiny interrupt latency, no unpredictable delays like heavy paging. Examples: FreeRTOS, VxWorks, QNX.

Multicore and cache issues

  • Cache coherence: each core has its own cache; hardware keeps copies consistent.
  • NUMA: memory close to a CPU is faster than memory attached to another CPU; the OS tries to place a process near its memory.
  • Lock-free programming uses atomic operations instead of locks.

Mobile OS notes

Android is built on the Linux kernel; iOS on Darwin/XNU. Both give each app a sandbox, manage battery aggressively, and may kill background apps instead of swapping them to disk.

11. Practice Problems with Answers

Try each one yourself first, then open the answer.

Q1. A process arrives at 2, needs 5 units of CPU, and completes at 12. Find TAT and WT.

TAT = CT − AT = 12 − 2 = 10. WT = TAT − BT = 10 − 5 = 5.

Q2. Round Robin, quantum 4. P1 (BT 10), P2 (BT 5), P3 (BT 8), all arrive at 0. Find the average waiting time.

Gantt: P1 0–4, P2 4–8, P3 8–12, P1 12–16, P2 16–17, P3 17–21, P1 21–23.
CT: P1 = 23, P2 = 17, P3 = 21. WT = CT − BT (AT = 0): 13, 12, 13.
Average WT = 38/3 = 12.67.

Q3. A counting semaphore starts at 5. After 7 wait() and 3 signal() operations, what is its value?

5 − 7 + 3 = 1. (Assuming none blocked because the value never forced a block incorrectly; with the textbook definition the value can go negative and it is still computed this way.)

Q4. 3 processes each need up to 2 instances of the same resource. What is the minimum number of instances that guarantees no deadlock?

Worst case: every process holds (max − 1) = 1 instance. Total held = 3. One more instance lets someone finish. Minimum = 3 × (2 − 1) + 1 = 4.

Q5. Page size 4 KB. Logical address 20,000. Page 4 is in frame 9. Find the physical address.

Page number = 20000 ÷ 4096 = 4 (4 × 4096 = 16384). Offset = 20000 − 16384 = 3616.
Physical = 9 × 4096 + 3616 = 36864 + 3616 = 40480.

Q6. 32-bit logical address, page size 4 KB. How many page-table entries?

Offset = 12 bits (4 KB = 212). Page number = 32 − 12 = 20 bits → 220 = 1,048,576 entries (1 M).

Q7. TLB access 10 ns, memory 100 ns, hit ratio 90%. Find the effective access time.

EAT = 0.9 × (10 + 100) + 0.1 × (10 + 200) = 99 + 21 = 120 ns.

Q8. Reference string 1 2 3 2 1 4 5 with 3 frames. How many page faults with LRU?

1 (fault), 2 (fault), 3 (fault), 2 (hit), 1 (hit), 4 (fault: replace 3, the least recently used), 5 (fault: replace 2). Total = 5 faults.

Q9. A process is 18 KB and the page size is 4 KB. How much internal fragmentation?

Pages needed = ⌈18/4⌉ = 5 pages = 20 KB. Wasted = 20 − 18 = 2 KB.

Q10. Disk head at 50. Requests: 82, 170, 43, 140, 24, 16, 190. Total head movement with FCFS?

50→82 (32), →170 (88), →43 (127), →140 (97), →24 (116), →16 (8), →190 (174).
Total = 32+88+127+97+116+8+174 = 642 tracks.

Q11. An inode has 12 direct pointers and 1 single-indirect pointer. Block size 4 KB, pointer size 4 bytes. What is the maximum file size?

Pointers per indirect block = 4096 / 4 = 1024. Total data blocks = 12 + 1024 = 1036.
Max size = 1036 × 4 KB = 4144 KB (about 4.05 MB).

Q12. A program calls fork() three times in a row (no conditions). How many processes exist in total?

Each fork doubles the number of processes: 1 → 2 → 4 → 8. Total = 2³ = 8 processes (7 new children).

PLACEMENT

🎯 Important Interview Questions

1. Process vs Thread?

A process is a program in execution with its own memory. A thread is a lightweight unit inside a process that shares the process's memory. Threads are faster to create and switch.

2. What is a context switch?

Saving the state of the running process (in its PCB) and loading the state of the next one so the CPU can switch between them. It is overhead.

3. What are the 4 conditions for deadlock?

Mutual exclusion, hold and wait, no preemption, circular wait. All four must hold together.

4. Mutex vs Semaphore?

A mutex is a locking mechanism owned by the thread that locked it. A semaphore is a signalling counter, which can allow N threads and can be signalled by a different thread.

5. What is starvation and how is it solved?

A process waits indefinitely because others keep getting priority. Solved by aging, which slowly raises the priority of waiting processes.

6. What is virtual memory?

A technique giving each process the illusion of a large private memory by keeping only needed pages in RAM and the rest on disk.

7. What is thrashing?

Excessive paging where the CPU spends more time swapping pages than doing real work, because there are too few frames per process.

8. What is Belady's anomaly?

In FIFO, increasing the number of frames can sometimes increase the number of page faults.

9. Internal vs External fragmentation?

Internal: unused space inside an allocated block. External: enough total free memory exists, but it is split into small non-contiguous holes.

10. What is a zombie and an orphan process?

Zombie: finished process whose entry stays in the process table because the parent has not read its exit status. Orphan: child whose parent has ended; it is adopted by init.

11. What is a system call? Give examples.

An interface through which a user program requests a kernel service. Examples: fork(), exec(), open(), read(), write(), wait().

12. Preemptive vs Non-preemptive scheduling?

In preemptive scheduling the OS can take the CPU away from a running process (RR, SRTF). In non-preemptive, a process keeps the CPU until it finishes or waits (FCFS, SJF).

13. Monolithic kernel vs microkernel?

A monolithic kernel runs all services (file system, drivers, networking) in kernel space: fast, but a bug can crash everything (Linux). A microkernel keeps only the minimum (scheduling, IPC, basic memory) in the kernel and runs the rest in user space: more secure and stable, but more message passing makes it slower.

14. What does fork() return and how many processes do 3 consecutive forks create?

It returns 0 in the child and the child's PID in the parent (−1 on failure). Three consecutive forks give 2³ = 8 processes in total (7 new).

15. User-level vs kernel-level threads?

User-level threads are managed by a library; switching is fast, but if one thread blocks in a system call the whole process blocks and they cannot use multiple cores. Kernel-level threads are managed by the OS; they are slower to create and switch but can run on multiple cores and block independently.

16. What is the convoy effect and how does SJF reduce waiting time?

In FCFS, a long process at the front makes many short processes wait behind it. SJF runs short jobs first, so the many short jobs finish quickly and the average waiting time is minimal. Its drawback is possible starvation of long jobs and that burst time must be predicted.

17. What is a Multilevel Feedback Queue?

Several ready queues with different priorities and quantums. New processes start at the top. A process that uses its whole quantum moves down; one that blocks early stays up; one that waits too long moves up (aging). It favours interactive jobs without knowing burst times in advance.

18. What is a race condition? Spinlock vs mutex?

A race condition is when the result depends on the timing of threads accessing shared data. A spinlock makes the waiting thread loop (busy wait), which is good for very short waits on multi-core systems. A mutex puts the waiting thread to sleep, which is better for longer waits because it frees the CPU.

19. How can the Dining Philosophers deadlock be avoided?

Allow at most N−1 philosophers to sit, pick both chopsticks atomically (only if both are free), or use an asymmetric order (odd philosophers pick left first, even pick right first), which breaks the circular wait.

20. What is a safe state?

A state where there is at least one order (safe sequence) in which all processes can complete using the current free resources plus what finished processes release. A safe state cannot deadlock; an unsafe state may (but need not) deadlock. The Banker's Algorithm only grants requests that keep the system safe.

21. Deadlock prevention vs avoidance vs detection?

Prevention makes one of the 4 conditions impossible by design. Avoidance uses advance information (maximum needs) and checks each request (Banker's). Detection lets deadlock happen, finds it with a graph or algorithm, and then recovers by killing or preempting.

22. Paging vs segmentation?

Paging uses fixed-size blocks and is invisible to the programmer, with no external fragmentation. Segmentation uses variable-size logical units (code, stack, heap) that the programmer sees, and it suffers from external fragmentation but matches protection and sharing needs better.

23. What is a TLB and why is it needed?

A small hardware cache of recent page-to-frame translations. Without it each memory access needs two accesses (page table, then data). With a high hit ratio the extra cost almost disappears.

24. Describe how a page fault is handled.

The hardware traps to the OS; the OS validates the address, finds the page on disk, picks a free (or victim) frame, writes the victim back if dirty, loads the page, updates the page table and restarts the instruction.

25. FIFO vs LRU vs Optimal?

FIFO evicts the oldest page and can show Belady's anomaly. LRU evicts the least recently used page and performs well since it uses recent past as a guide. Optimal evicts the page used farthest in the future, giving the minimum faults, but it needs future knowledge so it is only a benchmark.

26. What is copy-on-write?

After fork, parent and child share pages marked read-only. A page is copied only when someone writes to it. This makes process creation fast and saves memory.

27. Hard link vs soft link?

A hard link is another directory entry pointing to the same inode; the data stays until all links are removed and it cannot cross file systems. A soft link is a separate file that stores a path to the target; it breaks if the target is removed but can cross file systems and point to directories.

28. Interrupt vs trap?

An interrupt is an asynchronous signal from hardware (timer, keyboard, disk). A trap is a synchronous software-generated event, caused by the running program (system call, divide by zero, page fault). Both transfer control to the OS handler.

29. What is priority inversion?

A high-priority task is blocked waiting for a lock held by a low-priority task, while medium-priority tasks keep preempting the low one. The high task is effectively delayed by the medium ones. It is fixed with priority inheritance, where the lock holder temporarily gets the higher priority.

30. What happens when you switch on a computer?

The firmware (BIOS/UEFI) performs POST, finds the boot device and loads the bootloader. The bootloader loads the kernel into memory. The kernel initialises hardware and drivers, mounts the root file system, and starts the first process (init/systemd), which starts services and finally the login screen.
