1. What is Selenium WebDriver?

Selenium is a browser-automation project. WebDriver is its API for controlling a real browser such as Chrome, Firefox, Edge, or Safari. You write instructions in Java; WebDriver sends commands to the browser; the browser performs actions and returns results.

Selenium is for browser automation, not a general-purpose desktop automation tool. It does not replace API tests, unit tests, or performance testing.
BEGINNER

2. Setup and first test

  1. Install a supported JDK and an IDE such as IntelliJ IDEA or Eclipse.
  2. Create a Maven project.
  3. Add Selenium Java to pom.xml.
  4. Write a test and run it. Selenium Manager in modern Selenium can usually resolve browser drivers automatically; keep browser and Selenium versions current.
<dependency>
  <groupId>org.seleniumhq.selenium</groupId>
  <artifactId>selenium-java</artifactId>
  <version>4.x.x</version>
</dependency>

Use the current stable Selenium 4 version from the official release information instead of copying a version number from old notes.

import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;

public class FirstTest {
    public static void main(String[] args) {
        WebDriver driver = new ChromeDriver();
        try {
            driver.get("https://example.com");
            System.out.println(driver.getTitle());
        } finally {
            driver.quit();
        }
    }
}

get() navigates to a URL, getTitle() reads the title, and quit() closes the whole WebDriver session. Always close the session even when a test fails.

BEGINNER

3. WebDriver architecture and key interfaces

  • WebDriver: browser session controls such as navigation, window management, and element lookup.
  • WebElement: one element in the page, such as a button, input, or link.
  • By: locator strategies used to find elements.
  • WebDriverWait / ExpectedConditions: explicit waiting for a state.
  • Actions: advanced pointer and keyboard input.
  • JavascriptExecutor: execute JavaScript in the current browsing context when appropriate.
  • Alert, WebDriver.TargetLocator, Options, Navigation: interfaces for alerts, frames/windows, browser settings, and navigation.
Prefer normal WebDriver interactions and waits. JavaScript clicks can bypass real user interaction and hide genuine UI problems, so use them only when there is a clear reason.
BEGINNER

4. Locators: how Selenium finds elements

A locator is the address of an element. Prefer stable unique IDs or dedicated test attributes such as data-testid. Use CSS selectors for most straightforward cases and XPath when relationships or text-based selection make it clearer.

LocatorExampleWhen to use
IDBy.id("email")Stable unique ID.
NameBy.name("username")Form fields with name attributes.
Class nameBy.className("submit")One class token, not a space-separated list.
Tag nameBy.tagName("button")Find elements by HTML tag.
Link textBy.linkText("Contact")Exact visible text of an anchor.
Partial link textBy.partialLinkText("Cont")Partial anchor text; use carefully.
CSSBy.cssSelector("input[type='email']")Fast, readable attribute/structure selection.
XPathBy.xpath("//button[normalize-space()='Save']")Text, axes, and relationships.
WebElement email = driver.findElement(By.id("email"));
email.sendKeys("ram@example.com");

WebElement save = driver.findElement(
    By.cssSelector("button[data-testid='save']")
);
save.click();

Useful CSS patterns

By.cssSelector("#login")                  // id
By.cssSelector(".primary-button")         // class
By.cssSelector("input[name='email']")     // attribute
By.cssSelector("form input")              // descendant
By.cssSelector("ul > li")                  // direct child
By.cssSelector("button:disabled")          // disabled button

Useful XPath patterns

By.xpath("//input[@name='email']")
By.xpath("//button[normalize-space()='Submit']")
By.xpath("//label[normalize-space()='Email']/following::input[1]")
By.xpath("//div[contains(@class,'error')]")
By.xpath("//button[@type='submit' and not(@disabled)]")
Avoid brittle absolute XPath like /html/body/div[2]/div[1]/button. Small page changes can break it. Do not use By.className("one two"); className accepts one class token.

BEGINNER

6. findElement vs findElements

findElement(By)

Returns the first match. Throws NoSuchElementException if no match exists.

findElements(By)

Returns all matches as a list. If none exist, returns an empty list.

WebElement heading = driver.findElement(By.cssSelector("h1"));
List<WebElement> links = driver.findElements(By.tagName("a"));
System.out.println("Links: " + links.size());
for (WebElement link : links) {
    System.out.println(link.getText());
}

Use findElements() to count rows, links, menu items, or optional elements without catching a missing-element exception.

INTERMEDIATE

7. Waits: avoid flaky tests

Pages load asynchronously. A click may trigger an API call and the element may appear later. Waiting for the right condition is more reliable than guessing a fixed delay.

Implicit wait

Global element-search timeout.

driver.manage().timeouts().implicitlyWait(Duration.ofSeconds(5));
Explicit wait

Wait for a specific condition.

wait.until(ExpectedConditions.visibilityOfElementLocated(...));
FluentWait

Configurable timeout, polling interval, and ignored exceptions.

new FluentWait<>(driver)
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
WebElement login = wait.until(
    ExpectedConditions.elementToBeClickable(By.id("login"))
);
login.click();

wait.until(ExpectedConditions.urlContains("/dashboard"));

Common ExpectedConditions

  • visibilityOfElementLocated(locator) — element exists and is visible.
  • presenceOfElementLocated(locator) — exists in DOM, not necessarily visible.
  • elementToBeClickable(locator) — visible and enabled.
  • invisibilityOfElementLocated(locator) — hidden, absent, or stale element.
  • alertIsPresent() — browser alert exists.
  • urlContains(text), titleContains(text) — page navigation state.
  • numberOfElementsToBe(locator, n), stalenessOf(element) — list updates and old DOM references.
  • textToBePresentInElementLocated(locator, text) — expected text appears.
Do not mix large implicit waits with explicit waits; combined timeouts can behave unpredictably. Avoid Thread.sleep() except for a rare, justified debugging case.

Text inputs

Native HTML select

import org.openqa.selenium.support.ui.Select;
WebElement dropdown = driver.findElement(By.id("country"));
Select select = new Select(dropdown);
select.selectByVisibleText("India");

INTERMEDIATE

10. Actions: mouse and advanced keyboard

Use Actions for hover menus, right-click, double-click, drag-and-drop, and key combinations.

import org.openqa.selenium.interactions.Actions;
Actions actions = new Actions(driver);
WebElement menu = driver.findElement(By.id("menu"));
actions.moveToElement(menu).perform();
actions.contextClick(menu).perform();
actions.doubleClick(menu).perform();
actions.clickAndHold(menu).moveByOffset(100, 0).release().perform();
actions.keyDown(Keys.SHIFT).sendKeys("hello").keyUp(Keys.SHIFT).perform();
actions.scrollToElement(menu).perform();

Build an action chain, then call perform() to execute it. Drag-and-drop can be unreliable on some HTML5 applications; inspect the application behavior before assuming Selenium is at fault.

11. Alerts, frames, windows and tabs

JavaScript alerts

Alert alert = new WebDriverWait(driver, Duration.ofSeconds(5))
    .until(ExpectedConditions.alertIsPresent());
String message = alert.getText();
alert.accept();       // OK
// alert.dismiss();   // Cancel
// alert.sendKeys("text"); // prompt dialog

Frames and iframes

driver.switchTo().frame("payment-frame"); // name/id if supported
// or switch by WebElement / index
// driver.switchTo().frame(frameElement);
// driver.switchTo().frame(0);
driver.findElement(By.id("pay")).click();
driver.switchTo().defaultContent();
// driver.switchTo().parentFrame();

Multiple windows or tabs

String original = driver.getWindowHandle();
// click a link that opens a new window
ew WebDriverWait(driver, Duration.ofSeconds(5))
    .until(ExpectedConditions.numberOfWindowsToBe(2));
for (String handle : driver.getWindowHandles()) {
    if (!handle.equals(original)) driver.switchTo().window(handle);
}
System.out.println(driver.getTitle());
driver.close();
driver.switchTo().window(original);

getWindowHandle() returns the current window ID; getWindowHandles() returns all open window IDs. Never assume a newly opened tab is always at index 1; compare handles.

Stale element example

// Risky: page rerenders after clicking refresh
WebElement row = driver.findElement(By.id("row"));
driver.findElement(By.id("refresh")).click();
// Better: find the row again after the DOM update
WebElement updatedRow = new WebDriverWait(driver, Duration.ofSeconds(5))
    .until(ExpectedConditions.visibilityOfElementLocated(By.id("row")));
INTERMEDIATE

14. TestNG integration and assertions

Selenium controls the browser; TestNG organises tests, assertions, setup/teardown, data providers, grouping, and execution.

import org.testng.Assert;
import org.testng.annotations.*;
import org.openqa.selenium.*;
import org.openqa.selenium.chrome.ChromeDriver;

public class LoginTest {
    WebDriver driver;

    @BeforeMethod
    public void setUp() {
        driver = new ChromeDriver();
        driver.get("https://example.com/login");
    }

    @Test
    public void titleIsExpected() {
        Assert.assertTrue(driver.getTitle().contains("Example"));
    }

    @AfterMethod(alwaysRun = true)
    public void tearDown() {
        if (driver != null) driver.quit();
    }
}
  • @BeforeMethod / @AfterMethod: setup and cleanup per test method.
  • @BeforeClass / @AfterClass: setup and cleanup once per class.
  • @Test: marks a test.
  • Assert.assertEquals(actual, expected), assertTrue(), assertFalse(), assertNotNull(): verify outcomes.
  • @DataProvider: run one test with multiple data sets.
A test should assert the outcome, not merely perform clicks. For example, after login, assert a dashboard heading, URL, or logged-in user indicator.
ADVANCED

15. Page Object Model (POM)

POM puts page locators and page actions in dedicated classes. Tests describe scenarios; page classes describe how to interact with the UI. This reduces duplication and makes locator changes easier.

public class LoginPage {
    private final WebDriver driver;
    private final By username = By.id("username");
    private final By password = By.id("password");
    private final By submit = By.cssSelector("button[type='submit']");

    public LoginPage(WebDriver driver) { this.driver = driver; }
    public void login(String user, String pass) {
        driver.findElement(username).sendKeys(user);
        driver.findElement(password).sendKeys(pass);
        driver.findElement(submit).click();
    }
}
// Test: new LoginPage(driver).login("RAM", "secret");
Good POM

Locators and reusable page actions live in page objects; tests own assertions.

Test independence

Each test can run alone and cleans up its own browser/session state.

Maintainability

Use explicit waits, stable locators, small methods, and clear names.

ADVANCED

16. Building a maintainable framework

  1. Project structure: separate tests, page objects, utilities, test data, and configuration.
  2. Configuration: read base URL, browser, and timeouts from properties/environment variables.
  3. Driver lifecycle: create and quit sessions reliably; for parallel tests, isolate each thread's driver.
  4. Assertions: verify business outcomes and failure states.
  5. Diagnostics: capture screenshot, URL, browser logs where available, and exception details on failure.
  6. Reporting: publish TestNG/Maven results; use a reporting library only if project needs it.
  7. CI: run Maven tests in a clean environment; use headless browser execution where appropriate.
  8. Stability: avoid test-order dependence, hard sleeps, shared accounts/data, and brittle locators.

ThreadLocal concept for parallel execution

private static final ThreadLocal<WebDriver> DRIVER = new ThreadLocal<>();
// Each test thread gets its own driver instance.
// Always call DRIVER.get().quit() and DRIVER.remove() in teardown.
Do not share one WebDriver instance between parallel tests. Parallel execution also requires isolated test data, accounts, and cleanup.
ADVANCED

17. Advanced topics to know

  • Headless mode: run Chrome without a visible window using browser-specific options, e.g. ChromeOptions options = new ChromeOptions(); options.addArguments("--headless=new");.
  • Browser options/capabilities: configure browser arguments, preferences, proxy, downloads, and remote session capabilities.
  • RemoteWebDriver: execute tests against a Selenium Grid or remote browser endpoint.
  • Shadow DOM: locate the shadow host, access its shadow root with supported Selenium APIs, then find elements inside.
  • Relative locators: use RelativeLocator.with(By.tagName("input")).below(label) when positional relations are more robust than brittle selectors.
  • File upload: send an absolute file path to an <input type="file"> using sendKeys(path); native OS file dialogs are not generally controlled by WebDriver.
  • Downloads: configure browser download preferences and verify the downloaded file through filesystem checks; behavior differs by browser/CI environment.
  • Authentication: use safe test accounts and secret management; do not hardcode passwords or session tokens.
  • Accessibility: prefer accessible names/labels and verify keyboard behavior; Selenium itself is not a full accessibility audit tool.
ChromeOptions options = new ChromeOptions();
options.addArguments("--headless=new");
options.addArguments("--window-size=1440,900");
WebDriver driver = new ChromeDriver(options);
ADVANCED

18. Best practices checklist

  • Use Selenium 4 and current compatible browser versions.
  • Use stable IDs or dedicated test attributes where possible.
  • Prefer explicit waits for meaningful conditions; avoid arbitrary sleeps.
  • Keep tests independent and clean up browser sessions in finally or teardown hooks.
  • Assert visible outcomes, not implementation details alone.
  • Use Page Object Model for larger suites; avoid giant page classes.
  • Do not use JavaScript to force interactions unless justified.
  • Capture useful evidence on failure, but mask secrets and personal data.
  • Run tests in CI and investigate flaky tests instead of rerunning them forever.
  • Use API/database setup only when appropriate; retain UI tests for important end-to-end user journeys.
REVISION

19. Short notes to remember

  • WebDriver controls the browser; WebElement represents a DOM element.
  • By defines locator strategies; findElement() returns one match, findElements() returns a list.
  • click() clicks, sendKeys() types, clear() clears an editable input.
  • getText() reads visible text; getAttribute() reads an attribute; getDomProperty() reads a live property.
  • isDisplayed(), isEnabled(), isSelected() check state.
  • Explicit wait waits for a specific condition; do not rely on fixed sleeps.
  • Select works with native HTML select elements only.
  • Actions handles hover, context-click, double-click, and key chains.
  • switchTo() switches frames, windows, and alerts.
  • close() closes current window; quit() ends the full session.
  • POM separates page behavior from test scenarios.
  • TestNG manages test lifecycle/assertions; Selenium performs browser automation.
  • Stale element usually means the DOM changed; find the element again.
PLACEMENT PREP

20. Interview questions with short answers

1. What is Selenium WebDriver?

API for automating real browsers through browser-specific implementations and the WebDriver protocol.

It drives browser interactions and lets tests inspect page state.
2. Difference between findElement and findElements?

One returns the first match and throws when absent; the other returns all matches and an empty list when none exist.

3. What is the difference between implicit and explicit wait?

Implicit wait affects element searches globally; explicit wait polls for a particular condition.

4. Why is Thread.sleep discouraged?

It always waits the full duration, slowing tests and still failing when the application takes longer.

5. What causes StaleElementReferenceException?

The previously located element reference no longer points to the current DOM node, often after rerender/navigation.

6. What is Page Object Model?

A design pattern that encapsulates page locators and interactions in page classes.

7. How do you handle a dropdown?

Use Select for native HTML select; interact with custom dropdown options using locators and waits.

8. How do you handle multiple windows?

Save the original handle, wait for a new window, compare getWindowHandles(), switch to the new handle, then switch back as needed.

9. close() vs quit()?

close closes the current window; quit closes all windows and ends the WebDriver session.

10. How do you make UI tests less flaky?

Use stable locators, condition-based waits, independent test data, proper teardown, and meaningful assertions.

11. Can Selenium automate CAPTCHA?

It should not be used to bypass CAPTCHA. Use a test-environment bypass or test hook approved by the application team.

12. Does Selenium test APIs?

Not as its core purpose. Use an API testing tool/library such as REST Assured for API behavior and Selenium for browser UI behavior.

22. Practice tasks

  1. Open a practice website and print its title and URL.
  2. Find all links and print their count and text.
  3. Fill a login form, click submit, and assert an error or dashboard message.
  4. Select a country from a native dropdown and verify the selected option.
  5. Wait for a loading spinner to disappear before clicking a result.
  6. Switch to a newly opened tab and then return to the original tab.
  7. Capture a screenshot when a TestNG test fails.
  8. Refactor a repeated login flow into a Page Object Model class.
Learning rule: type the examples yourself, run them, deliberately cause a failure, and debug it. Memorizing method names without practicing locators, waits, and assertions will not make you interview-ready.
